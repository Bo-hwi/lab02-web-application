## Finding 1: A browser test can be executed with the wrong runtime

**Classification:** Verification failure reproduced during this audit; not an
application regression.

**Context and risk:** A generated instruction that runs every `*.test.js` file
with Node would include `tests/grid-event.test.js` and
`tests/grid-render.test.js`. These files require a browser DOM. Treating their
Node failure as evidence that the grid is broken would prompt an unrelated fix.

**Detection:** Running the following against the reviewed revision on
2026-10-30 exited with code 1:

```sh
node tests/grid-event.test.js
```

The error was `ReferenceError: document is not defined` at the test's
`document.getElementById("test-root")` call. This intentionally incorrect command
is a reproduction of the verification error, not a recommended test command.

**Corrective action:** Use the explicit Node suite listed below. Serve
`tests/grid-event-test.html` and `tests/grid-render-test.html` over HTTP for the
browser checks. Do not add fake DOM behavior to the production code to satisfy
a browser test run in the wrong environment.

**Verification and limit:** The correct Node suites passed 36 and 6 checks in
this audit. The historical T12 record reports browser event 8/8 and render
12/12 checks. Those browser results were not rerun today.

**Lesson:** Classify a test's required APIs before choosing its runtime.

## Finding 2: Console noise can be falsely attributed to application code

**Classification:** Historically recorded warning and currently reviewed
diagnostic risk; the warning's root cause remains unresolved.

**Context and risk:** The baseline, T05 and T07 entries in
[`HW1_VERIFICATION.md`](docs/verification/HW1_VERIFICATION.md) record a
Summarizer API warning while grid checks passed. An AI assistant could infer
that the grid caused the warning and change unrelated code.

**Detection:** The baseline explicitly says the warning's source had not been
established. Searching the current application JavaScript, `index.html` and
`mini-react.js` found no `Summarizer` or `summariz` reference. This absence does
not prove that a specific extension or browser component caused the warning.

**Corrective action:** Keep an unattributed warning separate from an application
exception. Investigate the console source URL, stack trace and a clean-profile
reproduction before assigning a cause or changing code.

**Verification and limit:** The Node tests passed. This audit did not reproduce
the warning in a browser and cannot establish its origin. The historical T12
record separately reports no browser console errors in its checked workflow.

**Lesson:** Missing evidence of a source is not evidence of a particular cause.

## Finding 3: Accessibility evidence can be overstated or merged across stages

**Classification:** Confirmed documentation-traceability gap and risk of
overclaiming; not a newly reproduced accessibility defect.

**Context and risk:** README and earlier audit text refer to Lighthouse scores
and manual screen-reader checks. An AI-written summary could combine these
into an unsupported claim of complete WCAG 2.2 AA conformance.

**Detection:** In the T13 section of
[`HW1_VERIFICATION.md`](docs/verification/HW1_VERIFICATION.md), the exact browser
version field still contains a placeholder. The same section says manual
screen-reader results are to be recorded separately, then states that several
screen-reader announcements were correct. T12 records a Chrome version for its
own run, but that is not proof of the browser used in T13. Earlier T11 text also
limits what was confirmed about spoken announcements.

**Corrective action:** Treat the Lighthouse 100/100 results and manual speech
claims as historical reports with these limitations. Do not fill the T13
version field by guessing or claim a new screen-reader test. A future evidence
update should record browser and assistive-technology versions, exact actions,
observations and date together in one consistent result entry.

**Verification and limit:** This update corrects the scope of the audit's claims.
It does not silently rewrite the historical report or resolve its missing
manual evidence. No Lighthouse, actual screen-reader speech, zoom/reflow or
full WCAG audit was performed on 2026-10-30.

**Lesson:** Automated scores, DOM semantics and actual spoken output are
different forms of evidence and must be reported separately.
